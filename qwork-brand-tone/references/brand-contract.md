# QWork 品牌契约

仅在任务涉及正式命名、产品文案、视觉方向、品牌审查或 E2E 品牌断言时读取。

## 权威顺序

1. 当前已批准的 PRD、Figma、品牌资产和产品决策；
2. `qwork-test-dataset` 中具备来源、版本和处置状态的 Requirement/Oracle；
3. QWork 仓库当前实现与语义 token，用于描述现状，不得自证为正确；
4. 本文的默认调性，用于来源未覆盖处，不得覆盖更高层事实。

无法确认来源时标记 `source-conflict` 或待确认，不把个人偏好写成强制规范。

## 当前稳定边界

- 面向用户的产品名统一为 `QWork`。
- `WorkBuddy` 只可出现在测试标题、来源说明和合法的参考对比中。
- QWork 使用自己的协议、bundle identity、账号、数据和服务状态。
- 不复制参考产品的 Logo、私有素材、账号数据、默认内容或品牌身份。
- 任何完成、连接、发布、保存和付费声明都必须与真实状态一致。
- 可访问性、安全、隐私和用户控制权不会为了视觉相似或营销表达而降低。

仓库内的主要证据入口：

- `docs/product-parity/qwork-clean-room-porting-prd.md`
- `docs/product-parity/qwork-visual-motion-contract.md`
- `src/renderer/src/styles/globals.css`
- `electron-builder.yml`

路径是发现入口，不等于版本固定的批准证明；审查前读取当前内容。

## 语言人格

| 维度 | 采用 | 避免 |
|---|---|---|
| 专业度 | 准确、直接、解释必要因果 | 官腔、术语堆砌 |
| 亲和度 | 平等、自然、尊重选择 | 撒娇、卖萌、过度拟人 |
| 能力感 | 明确已完成结果和下一步 | “无所不能”“一次搞定” |
| 诚实度 | 区分已完成、进行中、未验证 | 用成功语气掩盖不确定性 |
| 行动力 | 给出可执行动作和对象 | “请稍后重试”式无信息建议 |
| 克制度 | 一个界面一个主重点 | 多处高亮、感叹号和口号堆叠 |

## 常见触点

### 首页与空态

回答“现在能做什么”，提供一个明确入口。避免欢迎词占满首屏，也不虚构用户已经配置的能力。

### 进行中

描述真实阶段和可取消性。不要用百分比、预计时间或“马上完成”，除非系统确实提供可靠数据。

### 成功

先给结果和位置，再给可选下一步。只有业务结果与持久化证据成立时才能使用完成语气。

### 错误与恢复

结构优先为“发生了什么 → 有什么影响 → 怎么恢复”。未知根因写未知，不把外部服务、网络或用户操作当作默认责任方。

### 权限、费用与不可逆动作

在确认前说清动作、对象、范围、费用或不可逆后果；确认按钮使用具体动词，取消路径保持明显可达。

### Agent 回复

尊重模型正常输出。系统只补充宿主能够确认的状态，不以固定品牌文案替换真实结果。

## 视觉人格

- 当前实现以中性色构建层级，并通过 QWork 语义 accent 表达主操作；准确值从当前 token 读取。
- 使用系统无衬线字体、紧凑但不拥挤的间距与清楚的内容层级。
- 装饰服从任务，动效解释状态变化；不为“有科技感”添加无意义光效、渐变或持续动画。
- 品牌一致性覆盖浅色、深色、键盘焦点、禁用、错误、加载、最小窗口和三平台差异。

## 审查清单

- 名称、Logo、协议和来源身份是否正确；
- 首屏是否先回答用户最关心的结果；
- 是否存在过度承诺、伪成功或未经证实的根因；
- 高风险动作是否说明对象、后果和恢复边界；
- 按钮是否描述可预期动作，状态是否可区分；
- 视觉层级是否只有一个主重点并消费语义 token；
- Light/Dark、交互状态、可访问性和 reduced motion 是否完整；
- 需要进测试的判断是否已有可追溯 Oracle，而非只来自本 Skill。
