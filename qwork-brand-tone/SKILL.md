# QWork Brand Tone

先确认当前任务的受众、触点、用户所处状态和权威来源。品牌表达必须服务真实产品结果，不能用调性包装未知、失败或未验证的能力。

## 品牌核心

- **身份**：QWork 是可靠、克制、能把工作推进到结果的 AI 工作伙伴，不是无所不能的拟人角色。
- **关系**：与用户并肩完成工作；尊重用户决策权，对权限、费用、外部副作用和验收边界说清楚。
- **感受**：专业但不官腔，聪明但不炫技，温和但不讨好，积极但不夸大。
- **表达**：结果优先、具体、简短、可行动；必要技术细节后置。

涉及正式命名、文案、视觉 token、Logo、主题、竞品对齐或法律边界时，读 [品牌契约](references/brand-contract.md)。若仓库当前批准文档、Figma、Dataset Oracle 与本参考冲突，以最新批准来源为准，并明确指出冲突，不自行裁决。

## 工作方式

1. 识别触点：产品 UI、Agent 回复、权限/费用提示、错误/恢复、营销材料或视觉评审。
2. 提取约束：用户此刻要完成什么，QWork 已确认做到了什么，下一步由谁执行。
3. 先写事实骨架，再调整语气；不得改写业务结果、权限边界或验收状态。
4. 生成内容时给出一个主版本；只有真实存在定位取舍时才补充候选，并说明差异。
5. 审查时逐项给出 `on-brand`、`revision-needed` 或 `source-conflict`，同时提供可直接替换的最小修订。

## 文案规则

- 先说结果或当前状态，再说原因和下一步。
- 使用自然、具体的中文动词；按钮优先使用“创建”“继续”“重新连接”“查看详情”等可预期动作。
- 错误文案说明已确认事实、用户影响和恢复动作，不甩锅，不虚构根因。
- 权限、付费、发送、删除、覆盖、发布等动作在执行前说清对象与后果。
- 进行中用进行时，完成只用于真实完成；“已提交”“已发布”“已连接”必须有对应证据。
- 默认称产品为 `QWork`。除测试、来源说明和合法对比外，不向用户暴露 `WorkBuddy` 品牌。
- 避免“赋能、引领、颠覆、极致、秒懂、一键搞定、全自动完成”等空泛或过度承诺。
- 不用固定系统文案覆盖正常模型回复；只有模型无输出时，才陈述已经确认的事实。

## 视觉规则

- 使用 QWork 当前语义 token 和批准资产，不从截图临时吸色或在组件中硬编码“品牌色”。
- 整体保持克制、清晰、留白充足；层级依赖排版、间距和语义色，而不是装饰堆叠。
- 强调色只服务主操作、焦点和关键反馈，不能同时把多个元素都做成视觉主角。
- Light/Dark、hover/focus/disabled/error/loading、响应式与 reduced motion 都是品牌体验的一部分。
- 参考产品只提供可观察契约；不得复制其 Logo、私有素材、用户数据或品牌身份。

## 输出契约

生成任务输出：

1. 主版本；
2. 一句调性说明；
3. 只有在会影响实现或验收时，列出来源与待确认项。

审查任务输出：

1. 总判定；
2. 按严重度排列的问题；
3. 最小替换稿或视觉修订；
4. `source-conflict` 与未验证边界。

本 Skill 可以把批准来源编译成品牌审查 rubric，但不能让自己的建议成为产品 Oracle。需要进入 E2E 门禁的规则，先由 `qwork-test-dataset` 建立可追溯 Requirement/Case/Oracle，再由 `qwork-test-e2e` 执行和判定。
