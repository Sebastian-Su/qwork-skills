# 日报与周报模板

## 日报

默认使用面向领导和项目组的“成果版”。正文突出完成事项，不把内部验收记录原样搬进报告；完整日报仍保留所有栏目。

```markdown
**工作日报（YYYY-MM-DD）**

**今日工作**

1. 完成……，结果……。
2. 完成……，验证……。

**产出文档**

- [项目标识] 文档标题

**工作总结**

今日主要围绕……展开，已从……推进到……。

**未完成项**

下一步重点推进……；……仍需继续完善。

**明日尝试**

明日准备在……环节尝试……。最小验收信号是……。
```

日报默认规则：

- `今日工作` 保留 4—7 项独立成果，用编号列表。
- 固定保留 `今日工作 / 产出文档 / 工作总结 / 未完成项 / 明日尝试`，某栏暂无内容时写“无”或一句简短说明，不擅自删除。
- 用户只提供或重写某一栏时，仅替换该栏，其他栏目保持上一版原文；用户明确要求删除时才移除。
- `未完成项` 只写一到两句管理层可读的概括，不展开普通技术债、局部失败、内部红项和详细待办。
- 技术边界尽量正向表达，例如“完成专项验证”或“形成可安装版本”；只有涉及发布、上线等容易误判的状态时，补一句必要限定。

## 周报

```markdown
## 工作周报（YYYY-MM-DD—YYYY-MM-DD）

### 本周工作

1. 完成……，结果……。
2. 推进……，当前达到……。

### 产出文档

- [项目标识] 文档标题

### 工作总结

本周主要围绕……推进。已从……进入……阶段；总体判定为……。

### 未完成项

下一步重点推进……；其中……需要协调。

### 本周核心产出（100—200字）

本周围绕……完成……，关键结果为……；工作阶段从……推进到……。

### 本周关键收获：新范式下的成长

本周最大的变化是……。过去……，现在开始……，并通过……确认结果。

### 遇到的问题与对 AI Native 流程的建议

遇到的主要问题是……。建议在……环节加入……，并以……作为门禁，避免……。

### 下周更大胆的 AI 协作尝试

下周准备在……环节，首次尝试让 AI……。最小验收信号是……。
```

`明日尝试` 和 `下周更大胆的 AI 协作尝试` 先写入证据支持下的推荐项，再在草稿后提供不超过 3 个候选供用户替换。用户选择“不添加”时删除对应章节；用户确认提交时保留当前版本，不再追问。若用户提供了自己润色过的某一栏目，以该栏的信息密度和口吻作为优先风格样本，但不得据此删除或重写其他栏目。

补充已经发布的周报时，只生成以下增量回帖，不重复原周报：

```markdown
### 本周核心产出（100—200字）

……

### 本周关键收获：新范式下的成长

……

### 遇到的问题与对 AI Native 流程的建议

……

### 下周更大胆的 AI 协作尝试

……
```

## 证据化措辞

| 证据 | 可以写 | 不可以扩大为 |
|---|---|---|
| 代码或提交存在 | 已实现、已提交 | 已通过、已发布 |
| 聚焦测试绿色 | 目标测试通过 | 全量门禁通过 |
| 全量门禁绿色 | 本仓适用门禁通过 | 线上已验证 |
| 单次真实冒烟 | 最小真实链路通过 | 稳定性或能力达标 |
| develop/功能分支 | 已进入集成分支/功能分支 | 已发布 |
| 报告或会话自述 | 报告记录、会话声称 | 直接环境事实 |

## 简写示例

```markdown
**工作日报（2026-08-06）**

**今日工作**

1. 完成专家/专家团 v1 核心能力收口，实现负责人提问、动态并发和专家主身份注入，专家链路 E2E 6/6 通过。
2. 重建 UI 对齐门禁，补齐核心页面、状态和截图证据。

**产出文档**

- [qwork] 专家与专家团对齐 E2E 图文验收报告

**工作总结**

今日主要围绕专家能力交付、UI 对齐和证据留存展开，核心路径已形成专项测试证据。

**未完成项**

全量产品门禁和真实运行验证仍需继续收口。

**明日尝试**

明日继续推进真实运行验证，并以关键链路复测通过作为最小验收信号。
```
